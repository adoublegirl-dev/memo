给多个 AI 工具共用的本地项目档案室。

Memo 把散落在不同 AI 工具里的项目、知识、任务、偏好和来源线索，整理到同一个本地记忆系统。

WHY MEMO

AI 不缺回答，缺的是连续性。

当项目跨越几周、几个月，问题不再是“问一次能不能答对”，而是 AI 能不能理解你的历史、上下文、判断依据和偏好。

每次重新解释背景，都是一次上下文损耗。

01
项目背景总是丢换一个工具、换一次会话，前面聊过的约束和决定就需要重新铺垫。
02
判断依据无法追溯AI 给出结论后，你很难知道它依赖的是哪段材料、哪次讨论、哪个版本。
03
多个 AI 工具记忆割裂不同 Agent 各自有上下文，但它们没有一个共同的本地项目档案室。
HOW IT WORKS

从对话，到可追溯的本地记忆。

Memo 不只是保存几句话摘要，而是尝试保留来源、上下文和结构化线索，让后续 Agent 可以读到更完整的工作现场。

STEP 1
汇入对话与材料

从 Agent 对话、项目资料或手动记录中提取可用信息。

STEP 2
本地结构化整理

把事实、偏好、决策、任务和来源线索写入本地记忆库。

STEP 3
保留来源上下文

需要细读时，可回到完整原文，而不只是一句压缩摘要。

STEP 4
供多个 Agent 使用

通过 MCP 等方式，让不同 AI 工具访问同一套记忆。

USE CASES

更适合长期项目，而不是一次性问答。

Memo 的价值在于持续积累：项目越复杂、周期越长、参与的 AI 工具越多，它越像一个稳定的上下文底座。

项目交接

把项目背景、关键路径、坑点和最新状态整理成可复用记忆。

需求沉淀

保存产品判断、客户反馈、版本取舍和后续待确认事项。

排查记录

记录部署、依赖、脚本、服务和历史故障原因，避免反复踩坑。

个人偏好

让不同 Agent 逐渐理解你的表达风格、审美倾向和工作习惯。

FAQ

安装前常见问题。

这里先放最关键的几个说明，后续可以根据共测反馈继续补充。

我应该选择哪个数据目录？

选择 Memo 数据根目录即可，也就是包含 data、config、logs 的上一级目录。

更新会不会删除旧记忆？

不会主动打包或覆盖数据库、API Key、日志和备份。更新前仍建议保留自己的重要备份。

为什么 Full 安装包比较大？

Full 包内置本地运行时和依赖，目的是让新用户尽量一键安装，不被 Python 环境卡住。

Memo 会把我的数据传到官网吗？

官网只提供介绍和下载。你的记忆数据库默认保存在本机。
