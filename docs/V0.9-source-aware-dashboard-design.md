# Memo V0.9 Source-aware Dashboard 设计

> 状态：产品/信息架构设计稿。当前先不实现前端页面。

## 1. 设计目标

Source-aware Dashboard 不是普通聊天记录列表，而是一个“记忆来源审计工作台”。

它要回答四个问题：

1. 这条长期记忆来自哪个真实 Agent 会话？
2. 它来自哪几个原始 turn？
3. 这个 source_session 的原始标题是否可信？
4. 缺标题/低置信/工具日志等问题如何排队处理？

## 2. 页面结构

建议新增一级页面：

```text
/source-aware
```

下设四个视图：

```text
/source-aware/sessions
/source-aware/sessions/:id
/source-aware/missing-titles
/source-aware/memory/:id/evidence
```

## 3. Source Sessions 总览

### 3.1 列表字段

| 字段 | 说明 |
|---|---|
| 展示标题 | `display_title` |
| 原始标题状态 | 有 / 缺失 / fallback |
| 原始标题来源 | `title_source` |
| 展示标题来源 | `display_title_source` |
| Agent 来源 | `source_agent` |
| Turn 数 | `message_count` 或 source_turns count |
| Memory 数 | 关联 memory_units count |
| Evidence 数 | 关联 memory_turn_sources count |
| 更新时间 | `updated_at` |
| 风险标记 | missing title / generated fallback / high tool ratio 等 |

### 3.2 标题显示规则

标题区域必须同时表达两层含义：

```text
主标题：display_title
副标识：original_title: available / missing
```

如果 `display_title_source != agent_original`，标题旁显示标签：

```text
展示标题，不是原始标题
```

禁止在 UI 上把 display_title 直接叫“会话标题”。推荐叫：

```text
展示标题
```

原始标题单独叫：

```text
Agent 原始标题
```

## 4. Source Session 详情页

### 4.1 顶部信息卡

展示：

- source_agent；
- agent_session_id；
- source_path（home 路径脱敏）；
- source_hash；
- original_title；
- title_source；
- display_title；
- display_title_source；
- started_at / updated_at / imported_at；
- message_count；
- status。

### 4.2 Turns 面板

默认只展示元信息，不展示原文：

| 字段 | 说明 |
|---|---|
| turn_index | 原始顺序 |
| role | user / assistant / tool / system |
| content_length | 正文长度 |
| content_hash | hash 前 12 位 |
| timestamp | 时间 |
| source_event_type | 原始事件类型 |
| tool_name | 工具名 |
| is_final_answer | 是否最终回答 |

如果未来开启 `content_snapshot`，才允许展示正文，并需要权限提示。

### 4.3 Episodes 面板

展示：

- episode title；
- start_turn / end_turn；
- episode_type；
- boundary_confidence；
- related memory_units count。

交互：点击 episode 展开对应 turns。

### 4.4 Memory Units 面板

展示：

- memory content 摘要；
- memory_type；
- memory_granularity；
- speaker_scope；
- source_confidence；
- is_canonical；
- evidence links count。

交互：点击 memory 进入 Evidence Trace。

## 5. Evidence Trace 页面

路径：

```text
/source-aware/memory/:id/evidence
```

### 5.1 结构

```text
Memory Unit
  ↓
memory_turn_sources
  ↓
source_turns
  ↓
source_session
```

### 5.2 展示顺序

1. Memory Unit 卡片；
2. Evidence Links 表格；
3. 相关 Turns 时间线；
4. Source Session 信息；
5. 风险/置信度提示。

### 5.3 关键标签

- direct：直接证据；
- inferred：推断证据；
- context：上下文证据；
- conflict：冲突证据；
- source_confidence；
- boundary_confidence。

## 6. Missing Titles 队列

路径：

```text
/source-aware/missing-titles
```

### 6.1 入队条件

满足任一条件：

```text
title_source = missing
display_title_source != agent_original
```

### 6.2 列表字段

| 字段 | 说明 |
|---|---|
| 当前展示标题 | display_title |
| 展示标题来源 | display_title_source |
| Agent 来源 | source_agent |
| Turn 数 | turn count |
| 首个用户 turn 长度 | first user content_length |
| 更新时间 | updated_at |
| 操作 | 确认展示标题 / 手工改名 / 标记无需处理 |

### 6.3 操作规则

#### 确认展示标题

```text
display_title 保持不变
display_title_source = user_custom 或 confirmed_display
original_title 仍为空
```

当前 migration 枚举未包含 `confirmed_display`，若要使用需后续 migration；第一阶段可用 `user_custom`。

#### 手工改名

```text
display_title = 用户输入标题
display_title_source = user_custom
original_title 仍为空
```

#### 不允许操作

- 不允许把人工标题写入 `original_title`；
- 不允许批量用 AI 生成标题覆盖 `original_title`；
- 不允许隐藏 `title_source = missing` 的事实。

## 7. Dashboard 指标卡

首页顶部建议四张卡：

1. Source Sessions 总数；
2. Missing Original Titles 数；
3. Memory Units with Evidence 数；
4. Tool / Process Turns 占比。

辅助指标：

- source_agent 分布；
- title_source 分布；
- display_title_source 分布；
- memory_granularity 分布；
- speaker_scope 分布。

## 8. 第一阶段实现范围建议

MVP 只做：

1. Source Sessions 总览；
2. Source Session 详情；
3. Missing Titles 队列；
4. Memory → Evidence Trace 基础链路。

暂不做：

- 原文全文展示；
- AI 批量命名；
- 图谱可视化；
- 冲突合并；
- Persona/Todo 重接。

## 9. UI 文案原则

必须清楚区分：

```text
Agent 原始标题 ≠ Memo 展示标题
```

推荐标签：

- `原始标题可信`；
- `缺原始标题`；
- `展示标题来自首个用户问题`；
- `展示标题来自文件名`；
- `人工展示标题`。

不要使用：

- “自动恢复原始标题”；
- “AI 会话标题”；
- “真实标题”指代 display_title。
