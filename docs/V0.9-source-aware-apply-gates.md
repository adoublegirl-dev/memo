# Memo V0.9 Source-aware 真实导入闸门设计

> 状态：设计稿。当前代码仍只允许受保护测试库 apply；生产库 apply 不开放。

## 1. 目标

Source-aware 重建会把真实 Agent 历史重新拆成：

```text
source_sessions → source_turns → episodes → memory_units → memory_turn_sources
```

真实导入前必须让操作者明确知道：

- 将导入哪些 Agent 来源；
- 是否有可靠原始标题；
- 缺原始标题时如何生成展示标题；
- 是否会写入 raw content；
- 目标数据库是哪一个；
- 回滚依赖哪份备份。

## 2. 不可绕过红线

生产库真实导入前必须满足：

1. 服务已停止；
2. SQLite checkpoint 已执行；
3. 当前生产库已备份；
4. 备份 manifest 含 size 与 SHA256；
5. dry-run 报告已生成；
6. 用户明确确认本次导入来源、范围、标题策略与 raw content 策略；
7. 命令必须带生产专用 confirm token，不能复用 `TEST_APPLY`。

禁止：

- 删除数据库文件；
- 删除 / 移动 WAL / SHM；
- 未备份直接 migration / apply；
- 把 Memo 生成标题写进 `original_title`；
- dry-run 报告写入聊天正文或完整原始标题正文。

## 3. 建议命令分层

### 3.1 dry-run

```bash
python scripts/source_aware_import.py --source hanaagent --dry-run --limit 100
python scripts/source_aware_import.py --source workbuddy --dry-run --limit 100
python scripts/source_aware_import.py --source codex --dry-run --limit 100
```

输出报告到：

```text
reports/source-aware-import-<source>-<timestamp>.json
```

报告只能包含聚合信息：

- session 数量；
- turn 数量；
- estimated episodes / memory_units；
- title_sources 分布；
- display_title_source 分布；
- tool call / tool result 数量；
- risks；
- redacted source_path；
- 不含 raw content。

### 3.2 archive

```bash
python scripts/archive_current_db.py --apply --confirm ARCHIVE
```

输出：

```text
data/backups/memo-before-source-aware-<timestamp>.db
data/backups/env-before-source-aware-<timestamp>.txt
data/backups/archive-before-source-aware-<timestamp>.json
```

### 3.3 test apply

仅允许测试库：

```bash
python scripts/source_aware_import.py \
  --source workbuddy \
  --apply \
  --confirm TEST_APPLY \
  --db-path data/source_aware_test_workbuddy.db \
  --limit 10
```

`--db-path` 必须包含：

```text
test / dev / sandbox / dryrun / source_aware
```

### 3.4 production apply（未来实现）

生产导入必须使用独立命令/参数，建议设计为：

```bash
python scripts/source_aware_import.py \
  --source hanaagent \
  --apply-production \
  --confirm SOURCE_AWARE_PROD_APPLY \
  --db-path data/memo.db \
  --backup-manifest data/backups/archive-before-source-aware-<timestamp>.json \
  --dry-run-report reports/source-aware-import-hanaagent-<timestamp>.json \
  --title-policy preserve_original_else_display \
  --raw-content-policy hash_only
```

## 4. 标题策略

### 4.1 字段分工

| 字段 | 含义 | 可写入内容 |
|---|---|---|
| `original_title` | Agent 原始会话标题 | 只能来自 Agent 原始标题源 |
| `title_source` | 原始标题来源 | `session_titles_json_path` / `session_titles_json_id` / `db_title` / `missing` / `generated_fallback` |
| `display_title` | Memo 展示标题 | 可来自真实标题、首个用户问题、文件名、人工命名 |
| `display_title_source` | 展示标题来源 | `agent_original` / `first_user_turn` / `file_name` / `user_custom` 等 |

### 4.2 缺标题策略

当 `title_source = missing`：

```text
original_title = ''
display_title = 首个用户问题 compact 后文本；没有则文件名
display_title_source = first_user_turn / file_name
```

缺标题不阻断导入，但后续进入 Missing Titles 队列。

## 5. Raw content 策略

当前测试导入：

- `source_turns.content` 为空字符串；
- 只写 `content_hash` 与 `content_length`；
- memory_units 使用合成摘要占位，不写真实原文。

生产导入前必须二选一：

### A. hash_only（推荐第一阶段）

- 原文留在 Agent 原始 JSONL；
- Memo 只存 source_path、turn_index、hash、length；
- evidence chain 可回溯，但不复制全文。

### B. content_snapshot（后续增强）

- 对必要 turn 做原文快照；
- 需要单独隐私确认、加密/脱敏策略和清理策略；
- 不作为第一阶段默认方案。

## 6. 回滚策略

真实导入后如需回滚：

1. 停服务；
2. checkpoint；
3. 将当前 `data/memo.db` 另存为事故现场备份；
4. 用 manifest 对应备份恢复；
5. 校验 SHA256；
6. 再决定是否启动服务。

注意：回滚也不得删除 WAL / SHM，必须先 checkpoint 和备份现场。

## 7. 真实 apply 前确认文案模板

执行前应向用户展示：

```text
本次将对生产库 data/memo.db 执行 source-aware 导入。

来源：HanaAgent / WorkBuddy / Codex
范围：N 个 source_sessions，M 个 source_turns，预计 E 个 episodes，预计 U 个 memory_units
标题情况：original titled A，missing B，generated fallback C
展示标题策略：missing → first_user_turn，否则 file_name
raw content 策略：hash_only，不复制原始正文
备份：data/backups/memo-before-source-aware-xxxx.db
备份 SHA256：xxxx
回滚方式：停止服务后按 manifest 恢复备份

确认后才执行。未确认不会写入生产库。
```
